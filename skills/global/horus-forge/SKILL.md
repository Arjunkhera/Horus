# Horus Forge — MCP Tool Reference

Forge is split into two planes:

- **Local execution** — embedded inside the `horus-ui` container (port 8400), exposed as MCP at `/forge/mcp`. Handles `forge_develop` (git worktrees), workspaces, sessions, `forge_add`, and `forge_install`. All of these are **live**.
- **Control-plane registry** — served in-cluster at `https://horus.arjunkhera.io/api/v1/forge`, JWT-gated, S3-backed. Artifacts use the versioned layout `skills/<id>/<semver>/...`. A repo index (`forge_repo_register`, `forge_repo_get`, `forge_repo_list`, `forge_repo_resolve`, `forge_repo_update`, `forge_repo_remove`) is **live** as of 2026-06-01. Reads are public/anonymous; writes require a principal with `publisher` or `registry-admin` role (and tenant `default`).

> **Retired:** the old git-backed `Arjunkhera/Forge-Registry` GitHub repo and the standalone EC2/CloudFront registry are **gone**. All artifacts now live in the control-plane registry above. There is no `localhost:8744`, no CloudFront, and no `type: git`/`type: filesystem` registry.

## Active Tools

### Session and Workspace (local execution)

| Tool | Category | Purpose | Key Parameters |
|------|----------|---------|---------------|
| `forge_develop` | Sessions | Create (or resume) an isolated git worktree session linked to a work item | `repo` (required), `workItem` (required) |
| `forge_workspace_create` | Workspaces | Create a new named workspace (configures MCP connections, skills, permissions) | `name` (required), `config` |
| `forge_workspace_list` | Workspaces | List all workspaces | _(none)_ |
| `forge_workspace_delete` | Workspaces | Delete a workspace | `name` (required) |
| `forge_workspace_status` | Workspaces | Show current workspace status | _(none)_ |
| `forge_session_list` | Sessions | List active sessions | _(none)_ |
| `forge_session_cleanup` | Sessions | Remove stale worktrees | `dryRun` (optional) |

### Registry (control-plane, S3-backed)

| Tool | Category | Purpose | Key Parameters |
|------|----------|---------|---------------|
| `forge_search` | Registry | Search the registry for artifacts | `query` (required), `type` filter |
| `forge_resolve` | Registry | Inspect a single artifact + deps | `ref` (e.g., `"skill:horus-anvil@2.1.0"`) |
| `forge_add` | Registry | Add artifact refs to forge.yaml | `refs` (array, e.g., `["skill:sdlc-developer@^1.0.0"]`) |
| `forge_install` | Registry | Install all artifacts from forge.yaml | `dryRun`, `target` (claude-code/cursor/plugin) |
| `forge_list` | Registry | List installed or available artifacts | `scope` (installed/available), type filter |
| `forge_publish` | Registry | Publish an artifact to the registry | `ref` (required), `registry` (target registry id) |

### Repo Index (control-plane, live as of 2026-06-01)

| Tool | Category | Purpose | Key Parameters |
|------|----------|---------|---------------|
| `forge_repo_list` | Repos | List repos from the remote index | `query` (filter), `language` (filter) |
| `forge_repo_get` | Repos | Get a single repo record | `name` (required) |
| `forge_repo_register` | Repos | Register a new repo in the index | `name`, `url`, `language`, `description` |
| `forge_repo_resolve` | Repos | Resolve a repo name to a local clone path | `name` (required) |
| `forge_repo_update` | Repos | Update a repo's metadata | `name` (required), fields to change |
| `forge_repo_remove` | Repos | Remove a repo from the index | `name` (required) |
| `forge_repo_scan` | Repos | Trigger a full index rescan | _(none — config-driven)_ |
| `forge_repo_workflow` | Repos | Get/save git workflow config for a repo | `name` (required), `workflow` (optional, to save) |

## Sessions and Workspaces

Workspaces configure the agent environment (MCP connections, skills, permissions). They do **not** clone repos.

`forge_develop` creates an isolated git worktree linked to a work item. It auto-resumes existing sessions for the same repo+work-item pair. Use `forge_session_cleanup` to remove stale worktrees.

```
// Start or resume a coding session
forge_develop({ repo: "Horus", workItem: "ta-9" })
// → returns sessionPath (the worktree directory)
// All file edits go inside sessionPath
```

## Registry Architecture

Forge resolves artifacts from the registries listed in `forge.yaml`. On a managed Horus client this file is **generated by `horus setup`** and already points at the control-plane registry — you normally do not edit it.

### Registry type

V1 supports a **single** registry type: **`http`** — the control-plane registry at `https://horus.arjunkhera.io/api/v1/forge`.

> Any non-`http` registry is **rejected** by the schema. The legacy `git` (GitHub `Forge-Registry` repo) and `filesystem` (`~/Horus/data/registry/`) types are **retired** — remove any `type: git` or `type: filesystem` entries from `forge.yaml`.

### forge.yaml — engine config (generated by `horus setup`)

The Forge engine reads `~/Horus/data/config/forge.yaml`. `horus setup` writes it for you, pointing both registries at the control plane:

```yaml
registries:
  - name: local      # The names MUST be "local" and "global". Any other name
    type: http       # leaves the built-in defaults in play — keep these exact.
    url: https://horus.arjunkhera.io/api/v1/forge
    writable: true
    tokenEnv: TOKEN_PROVIDER_CONFIG
  - name: global
    type: http
    url: https://horus.arjunkhera.io/api/v1/forge
    tokenEnv: TOKEN_PROVIDER_CONFIG
```

> This file is marked `Managed by @arkhera30/cli`. `horus setup` regenerates it; hand-edit only after removing that marker (then setup leaves it alone).

### forge.yaml — workspace/install target

A workspace-config (or a `forge_add` target) lists the artifacts to install:

```yaml
artifacts:
  - skill:sdlc-developer@^1.0.0
  - plugin:anvil-sdlc-v2
  - workspace-config:sdlc-default@^1.0.0
```

## Artifact System

### Reference format

```
type:id@version
```

Examples: `skill:sdlc-developer@^1.0.0`, `plugin:anvil-sdlc-v2`, `agent:sdlc-implement-story@^1.0.0`

### Artifact types

| Type | Content File | Description |
|------|-------------|-------------|
| `skill` | `SKILL.md` | Opaque markdown emitted as agent instructions |
| `agent` | `AGENT.md` | Agent definition with root skill + dependencies |
| `plugin` | `PLUGIN.md` (optional) | Bundle of skills + agents |
| `persona` | `PERSONA.md` | Character profile — sets name, tone, expertise |
| `workspace-config` | `WORKSPACE.md` (optional) | Workspace template |

### Artifact storage layout (control-plane registry)

```
skills/<id>/<semver>/SKILL.md
skills/<id>/<semver>/metadata.yaml
agents/<id>/<semver>/AGENT.md
plugins/<id>/<semver>/PLUGIN.md
```

### Discovery workflow

```
1. forge_search(query)              // Find artifacts
2. forge_resolve(ref)               // Inspect metadata + dependencies
3. forge_add(refs)                  // Add to forge.yaml
4. forge_install()                  // Install to workspace
```

## Repository Index

The remote repo index is live. Use it to register, resolve, and discover repos.

```
forge_repo_list()                          // All indexed repos
forge_repo_list(query: "auth")             // Filter by name/description
forge_repo_resolve(name: "Horus")          // Get local clone path
forge_repo_register(name, url, ...)        // Register a new repo
forge_repo_scan()                          // Refresh index after cloning
```

### Git workflow config

```
forge_repo_workflow(name: "Horus")
```

| Workflow Type | Push To | PR Target |
|---------------|---------|-----------|
| `owner` | `origin` | Same repo |
| `fork` | `origin` (fork) | Upstream |
| `contributor` | `origin` | Upstream |

To save: `forge_repo_workflow(name: "Horus", workflow: { type: "owner", ... })`

## When to Use Forge vs Direct Git

| Scenario | Use |
|----------|-----|
| Starting work on a story or task (isolated worktree) | `forge_develop` |
| Creating a named environment with specific tools | `forge_workspace_create` |
| Listing / cleaning up active coding sessions | `forge_session_list` / `forge_session_cleanup` |
| Finding which repos exist in the index | `forge_repo_list` |
| Resolving a repo name to a local path | `forge_repo_resolve` |
| Registering a newly cloned repo | `forge_repo_register` or `forge_repo_scan` |
| Understanding a repo's PR workflow | `forge_repo_workflow` |
| Installing skills or plugins | `forge_add` + `forge_install` |
| Publishing a new artifact version | `forge_publish` |
| Browsing available tools | `forge_search`, `forge_list` |
| Committing changes inside a session | `git add <files> && git commit -m "..."` |
| Pushing + opening a PR | `git push -u origin <branch>` + `gh pr create` |

## MCP-over-HTTP Signal

The remote `/api/v1/forge` endpoint is MCP-over-HTTP (JSON-RPC, not REST). A plain `GET` returns `406 "must accept text/event-stream"` — this is expected and confirms the endpoint is live.
